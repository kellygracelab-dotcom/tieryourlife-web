# Web releases

For an assigned TierYourLife Web change, carry the release through to the public site after the checks pass. Use a branch, a pull request and a squash merge. Confirm the PR head passed both CI jobs, “Typecheck, lint, test, build” and “Against the proxy”. When a release depends on a newer shared Proxy, wait for its production confirmation before merging.

Once the release prerequisites are confirmed, run `npm run release:pr -- <PR number>` from either checkout. The command waits for the selected PR, accepts a PR already merged by GitHub, fast-forwards the main checkout and waits for CI on that exact commit. It deploys locally if the cloud job was skipped, or verifies a successful cloud deployment without deploying again. A failed cloud deployment is reported for investigation.

CI on a push to main deploys only `tieryourlife.web.app` and, if needed, its Web Functions codebase. The two required checks keep their names. The build job smokes and archives the production bundle with compiled Functions; four shards run the full browser matrix and the Proxy emulator suite stays mandatory. The production job restores the exact same-run artifact by run and SHA instead of rebuilding it. OIDC is restricted to this repo, push, main, .github/workflows/ci.yml and the web-production environment. The repository variables are FIREBASE_WORKLOAD_IDENTITY_PROVIDER and FIREBASE_DEPLOY_SERVICE_ACCOUNT. No long-lived key is needed. The owner manages IAM and environment protections.

Hosting-only delivery needs a verified receipt for the push currently served at /web-release.json, matching Functions inputs and matching live Google Cloud revision timestamps. Missing/expired proof, a partial deployment or changed inputs forces a full Web release. Production jobs serialize, recheck the remote tip immediately before and after upload, and verify the public revision, HTML, entry JS bytes and both API probes before recording success.

When OIDC isn't configured and the cloud job is skipped, the release command downloads the trusted, exact push artifact into an isolated checkout and uses the local Firebase CLI. It never rebuilds or repeats checks. An expired/missing artifact or a failed cloud job stops the command: rerun the main CI run to restore evidence. The canonical checkout is fast-forwarded; local dist is never treated as the release source.

After verification, confirm the canonical checkout, remote main and release SHA agree. Preserve the user's local files and edits, update active QA/preview paths, prune merged remote refs, and remove finished task branches and worktrees after checking their contents. Report the PR, commit, checks and production result.
